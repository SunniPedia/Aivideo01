1. ARCHITECTURE (non-negotiable)
- The whole video is a pure function of time. Each theme HTML file exposes window.init(rawTimestampsText, opts), which builds the DOM and returns the total duration (section 1B: audio length + tail, never shorter than the last scene end + 0.5 s hold); window.fit(), which shrinks each caption until it fits its panel and returns the chosen sizes; window.seek(t), which sets every style for time t; and window.setAudio(envelope, fps). opts carries project (from project.json), scenes (from scenes.json or null), badge (relative file name or null), logo (relative file name), logoData (the logo as a data URL, so the page can sample colors without a tainted canvas), audioDuration (seconds, or 0 when there is no audio) and tailPad (seconds).
- Forbidden inside the HTML and src files: CSS animations or transitions, setTimeout, setInterval, requestAnimationFrame, Date.now, Math.random, remote URLs (CDN, Google Fonts). Use deterministic sin-based motion so every render is identical. Intl.Segmenter is allowed (deterministic).
- render.js reads env THEME ('infographic' or 'podcast', default 'podcast') and picks the HTML file and the design size: infographic 1080x1920, podcast 1920x1080. It first probes the audio duration (section 7), then opens the page with Playwright (viewport = design size, deviceScaleFactor = WIDTH / design width, so smaller previews are just scaled), reads timestamps.txt, project.json and scenes.json, calls init with audioDuration and tailPad, waits for fonts and images, calls window.fit(), then loops over frames: seek(t) -> page.screenshot({type:'jpeg', quality:95}) -> write to FFmpeg stdin (image2pipe, mjpeg, handle backpressure with the drain event). Encode with libx264, crf 18, preset medium, yuv420p, +faststart, -r FPS, -t exact duration. Frame count = ceil(duration * FPS), so the last frame is never dropped.
- Environment variables: THEME; WIDTH (default = design width: 1080 for infographic, 1920 for podcast); FPS (default 30); OUT (default video-THEME.mp4, written to the root of the workspace; the file is never committed to the repo); START and END (render only a part, for tests; END defaults to the total duration); AUDIO_VOLUME (default 1.0); END_PAD (seconds the video continues after the audio ends; default 2.0 when an audio file exists, 0.5 when not; project.json endPad overrides the default); AUDIO_FADE_OUT (seconds, default 0.5, 0 disables).
- Log progress every 60 frames, log page errors, log the computed duration and its reason (section 1B), wrap main in try/catch and exit(1) on error.

1B. VIDEO DURATION AND ENDING (the video must never end abruptly)
- With an audio file: total = max(audioDuration + END_PAD, lastSceneEnd + 0.5). So the video ends END_PAD seconds (default 2.0) after the audio ends. If the audio is shorter than the timestamps, the video still runs to the last scene end + 0.5 s so no scene is cut, and the log prints a WARNING.
- Without an audio file: total = lastSceneEnd + END_PAD (default 0.5).
- The audio plays ONCE. It never loops. If it is shorter than the video, the rest is silence (section 7).
- Hold: the LAST scene stays fully visible (no fade-out) until the end of the video. When the video is longer than the last scene's end, the last scene's visible end is extended to the total duration (visual hold only). Spoken timing stays tied to the original timestamps: karaoke words, the host's mouth and arm gesture, the ON AIR sign and the speech presence sp use the original start and end of each scene; after the last scene's original end, sp eases to 0 over 0.3 s, the host goes idle (mouth closed, blinking, gentle head sway), the caption keeps the finished sentence, and the equalizer follows the audio level (which is 0 after the audio ends, see section 6).
- The progress bar fills over the whole total duration. The logo, closing icons and badge (the last scene's visuals) stay in their final state during the tail.
- If the audio is more than 1 s longer or shorter than the last timestamp end, log a WARNING with both numbers and the chosen duration (it is an information message, not an error).
- window.init returns the total and also exposes it as PV.timeline.total so render.js and tests read the same value.
- START and END (test ranges) are applied after the total is computed.

2. TIMESTAMPS PARSING (robust for any file)
- Strip a BOM, accept CRLF, ignore empty lines and lines starting with '#'. One scene per line: start | end | text | mood. The first two fields are times, the last field is the mood, everything between is the text (so a '|' inside the text is kept). If the last field is not a known mood and the line has only 3 fields, treat the 3rd as text and the mood as happy.
- Times: seconds with '.' or ',' as decimal, optionally m:ss.s. Mood is one of: respectful, happy, informative, excited, calm, enthusiastic (case-insensitive, trimmed). Unknown or missing mood -> happy.
- Markers ❝ and ❞ wrap a name to highlight in gold; remove the markers from the displayed text.
- Sort scenes by start. A line with empty text is skipped with a warning. If end <= start, set end = start + 0.5 and warn.
- Gaps between scenes are allowed (background only; in theme B the host stays idle). Overlaps are not: if lines overlap, warn and trim the earlier scene's end.
- A scene is visible from start-0.01 to end+0.01 (the last scene to the total duration, section 1B). Let dur = end - start. Enter: opacity easeOut over e = min(0.45, 0.4*dur) seconds plus translateY 40 px -> 0. Exit: fade over x = min(0.3, 0.3*dur). The LAST scene never fades out. All other motion timings inside a scene (sections 3, 6) are clamped to the scene duration so nothing is cut off, including scenes shorter than 1.2 s.
- Easing helpers: easeOut = 1-(1-x)^3, easeInOut (cubic), easeBack (overshoot 1.70158), prog(t, start, dur) = clamp((t-start)/dur).

4. COMMON DESIGN SYSTEM
- Palette: derived from the logo by common-palette.js, deterministically: draw opts.logoData to a canvas, sample a fixed grid, skip transparent, near-white and near-black pixels, quantize to hue buckets, take the dominant bucket as the accent color and the second as the highlight color (a light variant of the accent if there is only one), build the dark background colors from the accent by lowering lightness (a deep tone for the wall and a near-black for the vignette), and use a cream or white for text. If the logo has no usable colors or the project.json colors are set, use them; the fallback default is deep green #04210f and #0a4a2a, accent green #14804a, gold #e9c46a and #c9973a, cream #fff8e6. Check text/background contrast of at least 4.5:1 and adjust lightness if needed. 7. AUDIO
- If an audio file (.mp3, .wav, .m4a, .aac) exists in the repo root, use it as the sound track. The user uploads it; never create or modify it.
- tool-audio.js first probes the exact audio duration with ffprobe (format duration; fall back to decoded sample count) and gives it to render.js, which passes it to init (section 1B).
- tool-audio.js then analyzes it: decode with ffmpeg to mono 22050 Hz s16le, take RMS per video frame, normalize by the 95th percentile, smooth with attack 0.6 and release 0.18, then call window.setAudio(envelope, FPS). Log a WARNING when the audio is more than 1 s longer or shorter than the last timestamp end.
- Mux with ffmpeg input options '-ss START -i audio' (NO -stream_loop: the audio plays once), '-map 0:v -map 1:a', '-af afade=t=in:st=0:d=1.5 (only when START is 0), afade=t=out:st=(audioDuration - AUDIO_FADE_OUT):d=AUDIO_FADE_OUT (skip when AUDIO_FADE_OUT is 0), volume=AUDIO_VOLUME, apad=whole_dur=duration' (so the end tail and any gap after a short audio is silence and the audio stream lasts exactly as long as the video), aac 192k, and '-t duration' on the output. Do NOT use -shortest.
- The result: the audio ends at audioDuration, the video continues END_PAD seconds (default 2.0) in silence with the last scene visible, then ends. Never cut the audio and never end the video before the audio ends.
- No audio file: render a silent video and say so in the log.
